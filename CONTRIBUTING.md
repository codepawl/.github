# Contributing to CodePawl

CodePawl welcomes focused bug fixes, documentation updates, and product ideas.
Each repository can add project-specific requirements that override this guide.

## Before you open an issue

Search the repository's open and closed issues first. Use the bug report form for
reproducible defects and the feature request form for proposed behavior.

Do not report a vulnerability in a public issue. Follow the private reporting
instructions in the [security policy](SECURITY.md).

For usage questions or general support, follow the [support guide](SUPPORT.md).

## Write a useful bug report

Include:

- the version, release tag, or commit you tested;
- the operating system and relevant environment details;
- the smallest steps that reproduce the problem;
- the behavior you expected and the behavior you observed;
- relevant logs or screenshots after removing credentials and private data.

## Propose a product change

Describe the problem before the solution. Explain the proposed behavior, the
alternatives you considered, and any compatibility, privacy, or security impact.

## Submit a pull request

For a substantial behavior or architecture change, open an issue before writing
the implementation.

Keep the pull request focused. Follow the repository's build, formatting, and
test instructions. Add focused tests for behavior changes and update affected
documentation.

In the pull request description, list:

- the outcome and reason for the change;
- the commands or checks you ran and their results;
- known validation gaps or follow-up work;
- release, compatibility, security, privacy, or data impact.

Remove credentials, tokens, personal data, and unrelated generated files before
you submit the pull request.

All contributors must follow the [Code of Conduct](CODE_OF_CONDUCT.md).
